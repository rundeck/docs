# SPEC: RUN-2904 - Missing documentation on metrics

## Objective
Add a "Metric Types Reference" section to the Rundeck API docs that explains the meaning of every field returned by the `GET /api/V/metrics/metrics` endpoint, covering all four Dropwizard Metrics types: Gauge, Counter, Meter, and Timer.

## Approach
Insert a new subsection titled **"Metric Types Reference"** directly after the existing JSON response example in the "Metrics Data" section of `docs/docs/api/index.md`. The reference uses Markdown tables — one per metric type — listing each field, its unit, and a plain-language description. This keeps the docs co-located with the endpoint, requires no sidebar/navigation changes, and is consistent with how the rest of the API reference is structured (prose + example + field reference pattern used elsewhere in the file).

Alternatives considered:
- **New file + link**: More modular but adds navigation complexity and a cross-file maintenance burden for a relatively small addition.
- **Inline JSON comments**: Markdown/JSON doesn't support real comments; any workaround is non-standard and hard to maintain.

## Acceptance Criteria

- [ ] A "Metric Types Reference" subsection is added after the JSON example in the "Metrics Data" section of `docs/docs/api/index.md` -- Verification: manual
- [ ] The section covers all four metric types present in the API response: Gauge, Counter, Meter, and Timer -- Verification: manual
- [ ] Each metric type has a table with columns: Field, Type, Unit/Value, Description -- Verification: manual
- [ ] All Timer fields are documented: `count`, `max`, `mean`, `min`, `p50`, `p75`, `p95`, `p98`, `p99`, `p999`, `stddev`, `m1_rate`, `m5_rate`, `m15_rate`, `mean_rate`, `duration_units`, `rate_units` -- Verification: manual
- [ ] All Meter fields are documented: `count`, `m1_rate`, `m5_rate`, `m15_rate`, `mean_rate`, `units` -- Verification: manual
- [ ] Gauge and Counter fields are documented -- Verification: manual
- [ ] An introductory paragraph links the metric type terminology to Dropwizard Metrics (the underlying library) -- Verification: manual
- [ ] The docs site builds without errors after the change -- Verification: manual

## Scope
- **In scope:** Documenting the field-level semantics of the `GET /api/V/metrics/metrics` response in `docs/docs/api/index.md`
- **Out of scope:** Documenting individual named metrics (e.g., what `rundeck.services.NodeService.project.*.loadNodes` specifically measures); changes to the Configuration File Reference; adding monitoring dashboards or alerting setup guides; Histograms (currently empty `{}` in the API response and not in active use)
